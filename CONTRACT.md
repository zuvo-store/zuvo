# ZUVO — Build Contract (read this first)

Project: `~/workspace/zuvo`. Next.js 16 App Router + TypeScript (strict) + Tailwind CSS v4 + Prisma (SQLite, `prisma/dev.db`).

## Hard rules (Next 16)

- `middleware.ts` is DEPRECATED (renamed to `proxy.ts`, edge-only, no DB access). **Do not create either.**
  Route protection lives in server layouts: `app/account/layout.tsx` calls `requireUser()`;
  `app/admin/layout.tsx` checks `getSessionUser()` role and renders `<Forbidden/>` for non-admins.
- `cookies()` from `next/headers` is ASYNC — always `await cookies()`. (Already handled inside `lib/`.)
- Every API route file MUST start with `export const dynamic = "force-dynamic";`
- Server Components by default. `"use client"` ONLY for components needing interactivity
  (forms with state, cart buttons, search box, popups). Never import a server-only module
  (`lib/db`, `lib/auth`, …) from a client component — go through API routes or server actions.
- After a server action mutation, call `revalidatePath(...)` from `next/cache`.
- Import alias `@/` maps to the project root (`@/lib/db`, `@/components/X`).
- Money is ALWAYS integer cents in the DB and in API payloads. Format with `formatUSD()` from `@/lib/money`.
- NEVER hotlink external images. Product/category art lives at `/p/*.svg` (generated by the seed script);
  hero art at `/hero.svg` (foundation agent). Reference them as plain `/p/slug-01.svg` strings.
- No emojis in UI. No lorem ipsum. Every button/link must do something real.
- No zod, no extra deps — hand-rolled validation. `bcryptjs`, `nodemailer`, `prisma` are installed.

## Database (prisma/schema.prisma — SQLite; no enums, statuses are strings)

- `User`: id, name, username (unique), email (unique, normalized lowercase), passwordHash,
  role (`CUSTOMER`|`ADMIN`), emailVerified?, referralCode (unique, personal),
  referredById? → User, createdAt/updatedAt.
- `Session`: userId, tokenHash (unique, sha256 of cookie token), expiresAt.
- `EmailToken`: userId, tokenHash (unique), type (`VERIFY`|`RESET`), expiresAt, usedAt?.
- `Category`: name, slug (unique), description?, image? (`/p/*.svg`), sortOrder, active.
- `Product`: name, slug (unique), shortDesc?, description?, categoryId, brand?,
  priceCents (int), originalPriceCents? (int), currency (`USD`), stock (int),
  sku? (unique), rating (float), reviewCount, images (Json string[] of `/p/*.svg`),
  attributes (Json?), featured (bool), deal (bool, "Today's Deals"), active (bool).
- `ProductVariant`: productId, name (e.g. `Color`), value (e.g. `Red`),
  priceDeltaCents, stock, sku? (unique).
- `Review`: productId, userId?, authorName, rating (1-5), title?, body?.
- `CartItem`: userId? | guestToken?, productId, variantId?, qty.
- `WishlistItem`: userId, productId (unique pair).
- `Address`: userId, label, fullName, phone?, country, state, city, street, apartment?, postalCode, isDefault.
- `Order`: orderNumber (unique, `ZV-YYYYMMDD-XXXXXX`), userId?, guestName?, guestEmail?, guestToken?,
  status (`DRAFT`|`PENDING_PAYMENT`|`CONFIRMED`|`PROCESSING`|`SHIPPED`|`DELIVERED`|`CANCELLED`|`REFUNDED`),
  paymentStatus (`UNPAID`|`PENDING`|`SUCCEEDED`|`DECLINED`|`CANCELLED`|`FAILED`|`REFUNDED`),
  subtotalCents, discountCents, shippingCents, taxCents, totalCents, currency,
  contactJson?, addressJson?, deliveryMethod? (`STANDARD`|`EXPRESS`), deliveryLabel?, promoCode?.
  Relations: items (OrderItem[]), payments (Payment[]).
- `OrderItem`: orderId, productId?, variantId?, name, variantLabel?, image?, qty, unitPriceCents, lineTotalCents.
- `Payment`: orderId, provider (`demo`), scenario (`success`|`declined`|`pending`|`cancelled`|`error`),
  status, amountCents, currency, transactionRef? (unique), resultJson?.
- `RewardCampaign`: name, amountCents, currency, type (`SIGNUP`|`REFERRAL`), status (`ACTIVE`|`PAUSED`|`ENDED`),
  label (`DEMO — NO CASH VALUE`), terms?.
- `Reward`: userId, campaignId (unique pair), status
  (`AVAILABLE`|`PENDING`|`CLAIMED`|`EXPIRED`|`REJECTED`|`REVERSED`), amountCents, claimedAt?, expiresAt?, claimJson?.
- `RewardEvent`: rewardId, fromStatus, toStatus, note?.
- `ReferralAttribution`: referrerId, referredId (unique), code, status (`PENDING`|`ELIGIBLE`|`REJECTED`).
- `ReferralVisit`: code, createdAt.
- `Promotion`: code? (unique), title, description?, discountType (`PERCENT`|`FIXED`),
  discountValue (percent 1-90, or fixed cents), minOrderCents, active, startsAt?, endsAt?, usageLimit?, usedCount.
- `AuditLog`: actorId?, action, entity, entityId?, metaJson?.
- `Setting`: key (id), value.

## Conventions

- API route responses: `{ok:true, ...}` / `{ok:false, error:"…"}` with proper HTTP status (400/401/403/404/409/429).
- Forms in client components POST JSON to API routes; show server-returned errors; disable while pending.
- Admin mutations: server actions inside the page file (`"use server"`), then `revalidatePath`.
- Audit-log admin mutations that change money/state: orders, refunds, rewards, referrals, promos, settings.
- Dates: render with `new Date(d).toLocaleString("en-US")` (server components).
- Never expose passwordHash, tokenHash, or raw tokens in responses.
- Track-order page looks up by orderNumber + email (guest privacy) — never enumerates orders.
